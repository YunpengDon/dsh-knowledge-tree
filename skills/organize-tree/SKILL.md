# 整理知识树

## Overview
在 `工作区文件夹/knowledge-trees` 文件夹下，存储着用户的"知识树"。当用户与 AI 助手聊天的过程中学习到了新知识，可以将其整理为"树叶"添加到知识树中的"## 🍂 待整理"章节。本技能用于将待整理的"树叶"放到知识树中合适的节点"树枝"上。

## Instructions

### 1. 查看知识树结构
1. 读取知识树文件，查找所有标题行（`#` + 空格 + 文本），了解当前知识树的结构
2. 待整理的树叶位于"## 🍂 待整理"之后，每个树叶都是以 `### [日期]标题` 的格式开头，如 `### [2026/8/27] 深拷贝与浅拷贝：为什么需要复制数据？`
3. 如果待整理的树叶数量 > 0，则进入"2. 整理树叶"阶段。如果待整理的树叶数量 = 0，反馈用户当前没有找到待整理树叶，询问用户是否想要进行其他操作

### 2. 整理树叶
从第一个待整理树叶开始，对每一个树叶执行下面的循环，直到待整理树叶的数量为 0。

#### 2.1. 判断待整理树叶的归属
1. 从知识树结构中判断当前待整理树叶应该插入到哪一个节点，以及插入该节点的哪一个位置（最前、最末尾、某个树叶前、某个树叶后）
2. 如果文件中没有节点，或没有已存在的节点适合放置当前树叶，向用户推荐一个新的节点标题，询问用户是否要创建该新节点
3. 如果待整理的树叶已经存在于正文中，直接进入"2.3 清理已添加的树叶"

#### 2.2. 调用 `organize_tree` 整理知识树

`path` 相对 `knowledge-trees/` 解析，只传文件名（如 `python.md`），不要带目录前缀。

`organize_tree` 有 2 种模式：

- `op="insert_node"`（插入新节点）：
  - `anchor`：定位锚点节点标题（文档中已存在的标题）
  - `insert_at`：`"start"` 或 `"end"`，均指插入到**锚点子树范围内**的开头／末尾
  - `content`：新建的叶子或子节点文本

- `op="move_node"`（移动节点）：
  - `anchor`：目标节点标题
  - `insert_at`：`"start"` 或 `"end"`
  - `source_heading`：需要移动的节点标题
  - `new_heading`（可选）：搬移的同时改写源节点的标题，必须是单行标题（如 `"### 标题"`）。**把"待整理"里的树叶提升到正文时用它去掉标题里的日期**，这样无需把整片树叶的正文重新提交一遍
  - 注意：anchor 不能是 source_heading 自身或其子节点

**插入位置由“锚点 + start/end + content 的标题层级”共同决定**，没有单独的“之前／之后”取值：

| 目标位置 | 写法 |
|---------|------|
| 作为锚点 N 的子节点，排在 N 现有子节点之前 | `anchor=N, insert_at="start"`，且 `content` 标题比 N **深一级** |
| 作为锚点 N 的子节点，排在 N 现有子节点之后 | `anchor=N, insert_at="end"`，且 `content` 标题比 N **深一级** |
| 与 N 同级，插在 N **之后** | `anchor=N, insert_at="end"`，`content` 与 N 同级 |
| 与 N 同级，插在 N **之前** | `anchor=N 的父节点, insert_at="start"`（当 N 是其父节点的第一个子节点时）；否则 `anchor=N 的前一个兄弟节点, insert_at="end"` |

⚠️ 当 `content` 的标题层级与锚点**相同**时，新标题会终结锚点章节，锚点原有的子节点会被改挂到新标题之下。若目的只是新增一个同级分支，务必改用父节点或前一个兄弟节点作锚点；若确实想让新标题收纳锚点现有的子节点，这才是正确写法。

插入树叶时的注意事项：
1. 树叶标题文本中的日期需要删除。如 `### [2026/8/27] 深拷贝与浅拷贝` 插入正文时变为 `### 深拷贝与浅拷贝`
2. 如果需要为树叶创建新的节点标题，直接在插入内容最前方加上一行 `## [新节点标题]`

#### 2.3. 调用 `cleanup_organized_leaf` 清除已添加的树叶
使用 `cleanup_organized_leaf(path, leaf_heading)` 清除待整理区中的这条树叶。

#### 2.4. 反馈用户当前整理情况和剩余待整理的树叶数量
1. 回复用户：已经将"[树叶名]"插入到"[节点名]"下，还有 X 个待整理树叶
2. 如果待整理树叶的数量不为 0，自动进入下一个整理树叶的循环

### 3. 小结整理树叶的情况
1. 整理完所有树叶之后，回复用户已经完成所有树叶的整理，并询问用户是否要查看整理后的知识树结构
2. 如果用户需要更新知识树的索引文件中的介绍，可以调用 `update_index` 进行更新
3. 如果用户需要看新知识树的结构，整理为纯文本格式发送给用户，每一个标题一行
